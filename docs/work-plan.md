# 一期工作量与计划

## 工作量预估

以 1 名具备 Java、Vue、Python 和大数据基础的开发者估算，一期 MVP 约为 **36 至 48 人日**。如果是课程设计，采用演示数据、单机伪分布式 Hadoop 和单机 Flink，可压缩到 **20 至 28 人日**。

| 阶段 | 主要产出 | 预估人日 |
| --- | --- | --- |
| 需求细化与数据设计 | 原型、数据字典、接口契约 | 3-4 |
| 业务后端 | 账号、院校专业、收藏、导入审核 API | 8-10 |
| Flask 推荐服务 | 推荐评分、解释、单元测试 | 3-4 |
| 前端学生端与管理端 | 画像、检索、对比、推荐、导入页 | 8-10 |
| Hadoop/Hive 离线链路 | HDFS 分层、Hive 表、清洗聚合任务 | 5-7 |
| Flink 实时作业 | 热度、搜索词、数据更新事件流 | 4-6 |
| 联调、测试与部署 | 接口测试、演示数据、部署文档 | 5-7 |

## 迭代计划

### 第 1 迭代：基础数据与推荐闭环（第 1-2 周）

- 建立 MySQL 业务库、Hive 数仓分层和数据字典。
- 提供计算机相关专业院校演示数据与 CSV 导入模板，优先覆盖 0812、0835、0839、0854。
- 完成 Flask 推荐服务，返回冲刺、稳妥、保底及数学、408/自命题专业课匹配等可解释因素。
- 验收：可使用静态学生画像得到可解释的推荐结果。

### 第 2 迭代：业务服务与学生端（第 3-4 周）

- 实现 Spring Boot 院校专业检索、详情、收藏、对比、画像接口。
- 实现 Vue 学生端核心流程。
- 验收：学生可完成“填画像 -> 搜索 -> 比较 -> 获得推荐 -> 收藏目标”的闭环。

### 第 3 迭代：大数据处理链路（第 5 周）

- 导入历史数据到 HDFS ODS 层。
- 使用 Hive 构建 DWD 清洗表、DWS 院校专业年度指标表和推荐特征表。
- 实现 Flink 行为事件实时热度聚合。
- 验收：离线推荐特征与实时热门榜均可产出。

### 第 4 迭代：管理端、质量与部署（第 6 周）

- 完成数据导入审核、公告反馈和基础运营统计。
- 补充权限、日志、异常处理、接口测试和部署说明。
- 验收：系统从数据导入到学生端展示全流程可演示。

## 当前决策

一期不训练复杂机器学习模型。推荐先采用可配置的加权规则评分，原因是招生数据年度变化大、公开数据质量不均衡，并且规则模型可以清晰解释推荐原因。后续累计足够历史样本后，再增加学习排序或分类模型。
